# AQG — ต้นแบบเกมประเมิน AQ / GRIT

เว็บแอปเล่นในเบราว์เซอร์ ใช้วีดีโอ **S01 / S02 / S03** เป็นตัวเกม
**ตัวเลือกที่อยู่ในวีดีโอกดได้ทุกข้อ** และเก็บคะแนนตามเอกสาร *AQG scoring Aug*
พร้อมหลังบ้านรวมผลทุก session

---

## 1. รันระบบ

```bash
node server.js 5190
```

| อะไร | ที่ไหน |
|---|---|
| หน้าเล่นเกม | <http://localhost:5190> |
| หลังบ้าน (ผลรวมทุกคน) | <http://localhost:5190/admin.html> — **คีย์จะถูกสุ่มและพิมพ์ในคอนโซลตอนรัน** |
| โหมดสลับลำดับตัวเลือก | <http://localhost:5190/?panel=1> (ดูข้อ 6) |

ต้องรันผ่าน `server.js` (ไม่ใช่เปิด `index.html` ตรงๆ) เพราะวีดีโอไฟล์ละ 250–640 MB
ต้องใช้ HTTP range request — และไม่ต้องติดตั้ง dependency อะไรเลย (Node เปล่าๆ)

ตัวแปรสภาพแวดล้อม (ตั้งก่อนรัน):

| ตัวแปร | ความหมาย |
|---|---|
| `PORT` | พอร์ต (ค่าเริ่มต้น 5190) |
| `AQG_ADMIN_KEY` | คีย์เข้าหลังบ้าน — **ถ้าไม่ตั้ง ระบบจะสุ่มคีย์ใหม่ทุกครั้งที่รัน แล้วพิมพ์ในคอนโซล** (ไม่มีคีย์เริ่มต้นที่เดาได้) ตั้งค่านี้ถ้าต้องการใช้คีย์เดิมทุกครั้ง |
| `AQG_REQUIRE_CODE=1` | บังคับให้ผู้เล่นใส่รหัสเข้าเล่นที่ถูกต้องก่อนเริ่ม |
| `AQG_DEV=1` | เปิด `POST /_shot` สำหรับ dump เฟรมตอน calibrate cue |

PowerShell: `$env:AQG_ADMIN_KEY="รหัสของท่าน"; $env:AQG_REQUIRE_CODE="1"; node server.js 5190`

ตรวจความพร้อมก่อนเดโม/ติดตั้ง:

```bash
node tools/check.js
```

(ตรวจว่าทุกคำถามมี 5 ตัวเลือก คะแนนครบ 1–5 ตรง scoreMap, `slots` แม็พครบ,
ช่วง `cue` สมเหตุสมผล, ไฟล์วีดีโอ/ภาพ/สคริปต์ครบ)

## 3. การให้คะแนน

* `A=5, B=4, C=3, D=2, E=1` **ผูกกับ `choice_id`** (เช่น `S1_1_A`) ไม่ใช่ตำแหน่งบนจอ
* บันทึกต่อ 1 การตัดสินใจ: `choice_id`, `displayedPosition` (ช่องที่กดจริง A–E),
  `displayedOrder` (ผังตำแหน่ง→choice_id ของข้อนั้น), `responseTimeMs`, `timedOut`, `mode`, `timestamp`
* **20 วินาที/ข้อ** — หมดเวลา = `timedOut: true` คะแนน 0
* ไม่แสดงคะแนนหรือใบ้ใดๆ ระหว่างเล่น
* Result Screen: เรดาร์ + แท่ง 6 มิติ · Behavior Tag + คำแนะนำรายมิติ (ตามตัวเลือกที่เลือกจริง) ·
  จุดเด่น (4–5) · จุดที่ควรพัฒนา (1–2 เรียง GRIT-Perseverance ก่อนเมื่อต่ำ) ·
  **Dual-radar flag** (Control × Passion สูงพร้อมกัน = เสี่ยง overcommitment) ·
  raw log · Research note · ดาวน์โหลด **JSON / CSV** · ปุ่ม **พิมพ์/บันทึก PDF** (มี print stylesheet)

**จุดที่เอกสารไม่ได้ระบุ (ระบบเติมให้ แก้ได้)**

| เรื่อง | ที่ระบบใช้ | แก้ที่ |
|---|---|---|
| เกณฑ์ "สูงพร้อมกัน" ของ Dual-radar flag | ทั้ง Control และ Passion **≥ 4** (ตามเกณฑ์จุดเด่น 4–5) | `dualFlag.threshold` ใน `tools/gen_data.py` |
| หมดเวลาไม่ตอบ | คะแนน 0 + `timedOut: true` + ข้อความว่าควรทำซ้ำ | `answer()` ใน `app.js` |
| คะแนนรวม | ไม่ตั้งเป็นคะแนนทางการ แสดงเป็น "ค่าเฉลี่ยอ้างอิง" 3 ตัว | `computeResult()` ใน `app.js` |

**ทำไมบทบรรยายใช้ฉบับก่อนหน้า**: วีดีโอที่ render มาแล้วถูกพากย์ด้วยเนื้อเรื่องของฉบับ Aug 30
(ภารกิจ **"เข้าตียึดที่หมาย"**) — ยืนยันจากซับในวีดีโอ: S01 t=105s “จะให้ดำเนินการยึดที่หมายต่อ
หรือหยุดปฏิบัติภารกิจการครับ” · S03 t=46–50s “มีผู้ต้องสงสัยลักลอบวางระเบิดเข้าพื้นที่ /
ให้ติดตามจับกุมในโอกาสแรก” ถ้าการ์ดบรีฟใช้เนื้อเรื่องของฉบับล่าสุด ผู้เล่นจะเห็นบรีฟขัดกับเสียงในวีดีโอทันที

**ส่วนที่ให้คะแนนยึดฉบับล่าสุด 100%** และตรวจแล้วว่าตรงกับการ์ดในวีดีโอ —
4 ข้อที่สองฉบับใช้ข้อความต่างกัน (`S1_1_E`, `S1_3_C`, `S1_3_D`, `S1_4_E`) การ์ดในวีดีโอใช้ข้อความ
ของฉบับล่าสุดทุกข้อ (ซูมอ่านจากเฟรมจริง เก็บไว้ที่ `tools/shots/cards-check.jpg`)

เกณฑ์คะแนน · Behavior Tag · คำแนะนำ · โครงสร้าง · เวลา 20 วินาที **สองฉบับเหมือนกันทุกตัวอักษร**
(ต่างกันแค่เนื้อเรื่องและ 4 ตัวเลือกข้างต้น) การให้คะแนนจึงไม่ขึ้นกับว่าอ้างฉบับไหน

**ถ้า render วีดีโอใหม่จากฉบับล่าสุด** ให้แก้บรรทัดเดียวใน `tools/gen_data.py`:


แล้วรัน `python tools/gen_data.py` — บทบรรยายทั้งหมดจะสลับมาใช้ฉบับล่าสุดทันที (ทดสอบแล้วทั้งสองทาง)

---|---|---|
| คำถาม · inner question · **ตัวเลือก 30 ข้อ · คะแนน · Behavior Tag · คำแนะนำ** | **AQG scoring Aug** (ล่าสุด) → `tools/scoring_docx.txt` | อ่านการ์ดในวีดีโอ 4 ข้อที่สองฉบับต่างกัน (`S1_1_E`, `S1_3_C`, `S1_3_D`, `S1_4_E`) ตรงกับฉบับนี้ทุกข้อ |

แปลว่าเนื้อเรื่องด่าน 1 ที่ผู้เล่นได้ยินคือภารกิจ **“เข้าตียึดที่หมาย”** (ไม่ใช่ “รักษาความปลอดภัยพื้นที่”)
การ์ดบรีฟก่อนเข้าด่านจึงใช้ข้อความชุดเดียวกับที่พูดในวีดีโอ ไม่ขัดกัน

(ต่างกันแค่เนื้อเรื่องและข้อความ 4 ตัวเลือก) — การให้คะแนนจึงไม่เปลี่ยนไม่ว่าจะอ้างฉบับไหน

## 4. LOGIN และการเก็บผล

**แบบที่ใช้: รหัสเข้าเล่น (access code) — ไม่มีรหัสผ่าน ไม่เก็บข้อมูลส่วนบุคคลเกินจำเป็น**

1. แก้รายชื่อรหัสที่ [`config/access-codes.json`](config/access-codes.json)
   (แก้แล้วใช้ได้ทันที ไม่ต้องรีสตาร์ต) — เซิร์ฟเวอร์สร้างไฟล์ตัวอย่างให้ตอนรันครั้งแรก

   ```json
   { "codes": [ { "code": "AQG-001", "callsign": "ว2-001", "unit": "ร.๑ พัน.๑" } ] }
   ```

2. ผู้เล่นกด LOGIN → ใส่รหัส → ระบบเติมนามเรียกขาน/หน่วยให้อัตโนมัติ
   (ถ้าไม่ตั้ง `AQG_REQUIRE_CODE=1` จะข้ามได้ และกรอกนามเรียกขานเองก็ได้)
3. จบเกม → ระบบ **ส่งผลขึ้นเซิร์ฟเวอร์ทันที** และแจ้งสถานะบนหน้าผล (มีปุ่มลองใหม่ถ้าเน็ตสะดุด)

ผลถูกเก็บ 3 ทาง (กันหาย):

| ที่เก็บ | ไฟล์ / ที่อยู่ |
|---|---|
| ไฟล์ JSON ต่อ session | `results/<sessionId>.json` |
| log ต่อเนื่องทุก session | `results/sessions.jsonl` |
| สำรองในเครื่องผู้เล่น | `localStorage` คีย์ `aqg.sessions.v1` (50 ครั้งล่าสุด) + ดาวน์โหลด JSON/CSV |

> `results/` คือข้อมูลผู้เข้าร่วมจริง — อยู่ใน `.gitignore` แล้ว ควรสำรองและจำกัดการเข้าถึง

**หลังบ้าน `admin.html`**: จำนวน session · จำนวนข้อที่หมดเวลา · ค่าเฉลี่ยรวม ·
ค่าเฉลี่ยรายมิติ 6 มิติ (พร้อม n) · ตาราง session คลิกดูการตัดสินใจทั้ง 6 ข้อ ·
ปุ่มดาวน์โหลด **CSV รวมทุกคน**

### API

| endpoint | ใช้ทำอะไร |
|---|---|
| `GET /api/config` | แอปเช็คว่ามีเซิร์ฟเวอร์ไหม / ต้องใช้รหัสไหม |
| `GET /api/code?code=XXX` | ตรวจรหัสเข้าเล่น |
| `POST /api/sessions` | บันทึก 1 session (ตัวแอปเรียกเองตอนจบเกม) |
| `GET /api/sessions?key=…` | สรุปทุก session (ต้องมี admin key) |
| `GET /api/session?id=…&key=…` | รายละเอียด 1 session |
| `GET /api/sessions.csv?key=…` | CSV รวมทุกการตัดสินใจ |

**ถ้าไม่ได้รัน server** (เปิดไฟล์ตรงๆ / เซิร์ฟเวอร์ล่ม) แอปยังเล่นได้ครบ →
สลับเป็น *โหมดเดี่ยว* อัตโนมัติ เก็บผลใน localStorage + ดาวน์โหลดไฟล์ และแจ้งผู้เล่นบนหน้าผล

## 5. จุดสำคัญ: ตัวเลือกในวีดีโอ ↔ choice_id

วีดีโอ render จอคำถามมาแล้ว — การ์ด 5 ใบวางเป็นวงรอบนาฬิกา ติดป้าย A–E
**ตัวอักษรในวีดีโอไม่ตรงกับตัวอักษรในเอกสาร** (วีดีโอสลับตำแหน่งไว้แล้ว) เช่น
การ์ด “E” ของ Q01 คือ `S1_1_B` (4 คะแนน)

ตารางแม็พจริงอยู่ใน [`tools/gen_data.py`](tools/gen_data.py) (`CUES`) → generate ลง
[`data/game.js`](data/game.js) เป็น `slots` + ช่วงเวลา `cue` ของแต่ละคำถาม:

| คำถาม | ช่วงตอบในวีดีโอ (วินาที) | ตำแหน่งบนจอ → choice_id |
|---|---|---|
| S1_1 | 75.0 – 95.5 | A→A · B→C · C→E · D→D · E→B |
| S1_2 | 179.0 – 200.0 | A→B · B→E · C→A · D→D · E→C |
| S1_3 | 270.0 – 292.0 | A→D · B→A · C→C · D→E · E→B |
| S1_4 | 359.0 – 376.0 | A→E · B→B · C→D · D→C · E→A |
| S4_1 | 121.0 – 143.0 | A→C · B→D · C→B · D→A · E→E |
| S7_1 | 95.0 – 113.0 | A→E · B→D · C→B · D→A · E→C |

พฤติกรรมของแอปที่จุดตัดสินใจ:

1. วีดีโอถึง `cue.start` (การ์ดครบ 5 ใบ) → ขึ้น **hotspot โปร่งใสทับการ์ดจริง** + นาฬิกา 20 วินาที
2. วีดีโอถึง `cue.end` ก่อนผู้เล่นตอบ → **หยุดภาพค้าง** ผู้เล่นยังได้เวลาครบ 20 วินาที
3. เลือกแล้ว (หรือหมดเวลา) → ข้ามช่วงนับถอยหลังของวีดีโอไปที่ `cue.end` แล้วเล่นเรื่องต่อ

**ปุ่ม/คีย์ระหว่างเล่น**: `A`–`E` หรือ `1`–`5` เลือกคำตอบ ·
`F` เต็มจอ · `M` ปิด/เปิดเสียง · `Esc`/`Space` ข้ามไปจุดตัดสินใจถัดไป (ใช้ไม่ได้ขณะกำลังตัดสินใจ)

การเลือกคำตอบใช้ **การกดการ์ดในวีดีโอเท่านั้น** ไม่มีแผงข้อความซ้อนทับ
(เดโมควรเล่นบนจอใหญ่/เต็มจอ เพื่อให้อ่านการ์ดในวีดีโอได้สบาย)

### ถ้าเปลี่ยนไฟล์วีดีโอ ต้อง calibrate ใหม่

```bash
AQG_DEV=1 node server.js 5190     # เปิด /_shot เพื่อ dump เฟรม
```

ในคอนโซลเบราว์เซอร์: seek ไล่ทีละช่วงเพื่อหา “ช่วงที่การ์ดครบ 5 ใบ → จอคำถามหายไป”
แล้วอ่านข้อความการ์ดแต่ละใบเทียบกับ `tools/options.json`
จากนั้นแก้ตาราง `CUES` ใน `tools/gen_data.py` → `python tools/gen_data.py` → `node tools/check.js`
(เฟรมที่ใช้ calibrate รอบนี้อยู่ใน `tools/shots/`)

## 6. Panel mode (`?panel=1`)

เอกสารกำหนดให้ **สลับลำดับตัวเลือกต่อ session** ซึ่งทำกับตัวเลือกที่ render ติดมาในวีดีโอไม่ได้
โหมดนี้จึงเป็นทางเลือก: ถึงจุดตัดสินใจแล้ว **หยุดภาพวีดีโอ** และแสดงตัวเลือกทั้ง 5 เป็นรายการของระบบเอง
**สลับลำดับใหม่ทุก session** — คะแนนยังผูกกับ `choice_id` เหมือนกัน และ log บันทึก `mode: "panel"` ไว้แยกวิเคราะห์

โหมดปกติ (`video`) ไม่สลับลำดับ แต่ผัง A–E ในวีดีโอเองสลับไว้แล้ว (ตำแหน่งไม่ไล่ตามคะแนน)
และทุกการตัดสินใจบันทึกตำแหน่งที่แสดงครบ เพื่อวิเคราะห์ position bias ภายหลัง

## 7. Performance ที่ทำไว้

* **HTTP range + conditional GET (ETag/Last-Modified)** — เล่นซ้ำ/ย้อนด่านไม่ดาวน์โหลดใหม่
* **gzip** สำหรับ html/css/js/json · **cache 7 วัน** สำหรับวีดีโอและภาพ
* **prefetch** หัวไฟล์วีดีโอด่านถัดไป (1 MB แรก) ตอนผู้เล่นอ่านการ์ดบรีฟ → กดเข้าแล้วเริ่มเล่นทันที
* **poster จากเฟรมจริง** ของแต่ละด่าน (`assets/poster-s0*.jpg`) — ไม่เห็นจอดำตอนโหลด
* **spinner** เฉพาะตอนสตรีมสะดุด และไม่ขึ้นทับจอตัดสินใจ
* ภาพพื้นหลัง/โลโก้ย่อ+optimize แล้ว (assets รวม ~1.8 MB)
* เมื่อกดตอบ ระบบ seek ข้ามช่วงนับถอยหลังทันที ไม่ปล่อยให้รอ

### วีดีโอรุ่นเว็บ (ทำแล้ว)

ต้นฉบับ 1080p25 ที่ 13–17 Mbps (รวม ~1.2 GB) ถูก re-encode เป็น **`video/S0X-web.mp4`**
ที่ CRF 22 / preset medium / AAC 128k / faststart → **เล็กลงประมาณ 4.5 เท่า**
ตัวหนังสือไทยบนการ์ดตัวเลือกยังคมชัด (ตรวจแล้วเทียบเฟรมต่อเฟรม)

* แอปจะใช้ `-web` ก่อน และ **ถอยไปใช้ไฟล์ต้นฉบับอัตโนมัติ** ถ้าไม่พบ/เล่นไม่ได้
  (`videoFallback` ใน `data/game.js`) — ไฟล์ต้นฉบับเก็บไว้เป็น master ได้เลย
* จังหวะ `cue` ไม่เปลี่ยน เพราะ re-encode ไม่ได้ตัดต่อเนื้อหา

ถ้า render วีดีโอชุดใหม่ ให้ย่อด้วย:

```powershell
.\tools\compress-video.ps1            # หรือ -Crf 20 ถ้าต้องการคุณภาพสูงขึ้น
node tools\check.js
```

## 9. ข้อควรรู้ / ที่ยังไม่ได้ทำ

* **ความปลอดภัย**: ระบบนี้ออกแบบสำหรับรันในเครือข่ายที่ควบคุมได้ (เครื่องเดียว/LAN ของหน่วย)
  ไม่มี HTTPS, admin key เป็น key เดียว — ถ้าจะเปิดสู่อินเทอร์เน็ต ต้องมี reverse proxy + TLS
  และตั้ง `AQG_ADMIN_KEY` เป็นคีย์ที่คาดเดายากก่อน
* **เสียงพูดตัวเลือกทีละข้อ (ปุ่ม Play)** ตามสตอรี่บอร์ด `S05/1` ยังไม่ได้ทำ —
  วีดีโออ่านตัวเลือกให้ครบแล้วในตัว
* สตอรี่บอร์ด `AQG Game.pdf` ระบุคะแนนแบบเก่า (Control +2 / Ownership +1) และนับถอยหลัง 10 วินาที
  — ระบบยึด **เอกสาร scoring (A=5…E=1, 20 วินาที)** เป็นหลัก
* เบราว์เซอร์บางตัวห้ามเล่นวีดีโอมีเสียงอัตโนมัติ — การกด START/เข้าสู่สถานการณ์นับเป็น user gesture
  จึงเล่นได้ปกติ ถ้าเงียบให้กดปุ่ม **เสียง** (หรือ `M`)
* ยังไม่ได้ทดสอบบนมือถือจริง (ทดสอบด้วย viewport emulation เท่านั้น)
